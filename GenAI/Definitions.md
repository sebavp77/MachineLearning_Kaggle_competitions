- **context length**: number of tokens the model can "remember" and use to predict the next token in the sequence. Longer context length potentially could lead to better model performance but it also means a higher computational burden. 
- **Supervised fine tuning (SFT):** Process of improving an LLM's performance on a specific task or set of tasks by further training it on domain-specific, labeled data. The LLM is generally exposed to positive examples, i.e. high-quality demonstration data.
- **Reinforcement learning from human feedback (RLHF)**: This is a second stage of fine-tuning, it enables an LLM to better align with human-preferred responses. In this approach the LLM is exposed to positive and negative examples, by penalizing the model with negative examples it is less likely to generate unhelpful or unsafe responses.
- **Parameter efficient fine-tuning (PEFT)** These are a set of fine-tuning techniques with a cheaper computational cost than SFT and RLHF. These techniques  considered a subset of weights from the whole model that are used to "perturb" the pre-trained LLM weights. Some common PEFT techniques are:
	- **Adapter-based-fine-tuning** It employs small modules (called adapters) to the pretrained model and only parameters of these adapters are trained.
	- **Low-Rank Adaptation (LoRA)** it uses two smaller matrices to approximate the  original weight matrix update instead of fine-tuning the whole LLM. The original weights are frozen and trains these update matrices. An alternative approach is **QLoRA** which uses quantized weights. ==One nice feature about LoRA is that they can be plug and play, meaning you can train one LoRA that specializes in one task and easily replace it with another LoRA==.
- **Soft prompting** Technique for conditioning frozen large language models with learnable vectors instead of hand-crafted text prompts.
- **Prompt engineering** process of designing and refining the text inputs that you feed into an LLM to achieve desired and relevant outputs. #prompt_engineering 
- **Sampling technique** It determines the way in which output tokens are chosen and influence the correctness, creativity, and diversity of the resulting output.
- **Retrieval-Augmented Generation (RAG):** It is an AI framework that improves LLM by searching an external knowledge database for relevant facts before generating a final answer. RAG is intended to tailor the LLM response with relevant information to the task such as specific documents, databases, company files without needing to retrain the model, #RAG. typical workflow:
	- **Indexing:** Documents are tokenized
	- **Retrieval:** When you type a question, the system searches the database to find the text pieces that best match your meaning
	- **Augmentation:** The system combines the original question with the retrieved text pieces into a single prompt for the AI
	- **Generation:** The LLM reads the provided text context and writes an accurate, grounded answer
